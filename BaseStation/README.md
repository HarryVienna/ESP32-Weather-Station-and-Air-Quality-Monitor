# ESP32 Weather Station & Indoor Air Quality Monitor — Base Station

*[Deutsch](README_de.md)*

A base station built around the **ESP32-P4** with a 10.1" touchscreen that brings together weather
data from the internet, a built-in air quality sensor, and up to six battery-powered wireless sensors
(LoRa / ESP-NOW) — including a Geiger counter — on a single display.

> This is one component of a larger project — see the
> [repository root README](../README.md) for the full system overview and a photo of the hardware.

## Overview

The overall system consists of three parts:

1. **This base station** (ESP32-P4 + touchscreen) — displays all the data and is the only part you
   actually interact with.
2. A **Sensor Receiver** (ESP32-S3) that collects LoRa and ESP-NOW packets from the wireless sensors
   in the background and forwards them to the base station over I2C.
3. Several **battery-powered wireless sensors** (temperature/humidity, some with barometric pressure,
   plus a Geiger counter), which spend most of their time in deep sleep and only transmit
   periodically.

The base station itself also has a built-in **SEN66** sensor (particulate matter, VOC, NOx, CO₂,
temperature, humidity) and fetches the weather forecast from the internet over WiFi.

## Features

- Live display of all connected sensors (up to 6 wireless sensors + the built-in SEN66)
- 24h history charts with peak bucketing — short spikes (e.g. a brief rise in particulate matter)
  stay visible in the chart instead of disappearing into an average
- Color-coded thresholds for battery voltage, signal strength, particulate matter, VOC, NOx, CO₂ and
  radiation
- Weather forecast from three selectable providers (Open-Meteo, OpenWeatherMap, VisualCrossing) with
  hourly and daily charts
- Geiger counter integration, including its own radiation color scale and 24h history
- Automatic display brightness based on ambient light and presence sensing
- Fully configurable from the touchscreen (WiFi, location/timezone, sensor icons) — no reflashing
  needed for basic setup
- Per-slot offline watchdog: a sensor card's header turns red once that sensor hasn't reported in for
  a while

## Hardware

| Component | Part |
|---|---|
| Board | Waveshare ESP32-P4-Module-DEV-KIT |
| Display | Waveshare 10.1" DSI touch (800×1280, run in 1280×800 landscape) |
| Touch controller | GT911 (capacitive) |
| Built-in air quality sensor | Sensirion SEN66 |
| Ambient light sensor | BH1750 |
| Presence sensor | C4001 (mmWave radar) |
| WiFi | routed through an ESP32-C6 co-processor via esp-hosted (the P4 has no native WiFi radio) |
| Wireless counterpart | Sensor Receiver (ESP32-S3), receives LoRa (SX1262) + ESP-NOW and forwards over I2C |

## Getting started

Requires **ESP-IDF v5.5.4** (other 5.5.x versions are likely compatible but untested).

```powershell
git clone <repo-url>
cd BaseStation
idf.py set-target esp32p4
idf.py build
idf.py -p COMx flash monitor
```

On first boot, the base station shows the setup screen: pick a WiFi network, enter
location/timezone, choose a weather provider (+ API key if needed), and assign an icon to each of
the 6 sensor slots. Everything is stored in NVS and survives a reboot.

> **Note:** `main.c` contains an additional, hardcoded WiFi connection attempt at boot. It exists
> solely for the automatic screenshot task used during development (see `start_screenshot()`) — it's
> not needed for normal operation, since the actual WiFi setup happens through the setup screen.
